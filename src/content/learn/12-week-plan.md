> **适用对象**：有 1 年以上 B 端产品经验，想系统转型 AI 产品经理
> **周期**：12 周（约 3 个月）· **建议投入**：工作日每天 1-2 小时，周末 3-4 小时

你已经有 B 端底子（业务流程、权限、数据流、PRD、跨团队协作）。要补的是技术理解和 AI 产品方法论。下面这份计划不追求「学完」，追求「每周交出一份能用的东西」。

## 你已具备 vs 需要补的

| 能力维度 | B 端 PM（你已具备） | AI PM（需要补） |
| --- | --- | --- |
| 业务理解 | 业务流程、权限体系、数据流 | + AI 可介入的业务节点识别 |
| 需求分析 | 用户访谈、场景拆解 | + AI 能力边界评估 |
| 产品设计 | PRD、原型、交互 | + Prompt 设计、AI 交互范式 |
| 技术理解 | 了解基本技术栈 | ⭐ 必须掌握 LLM 原理、RAG、Agent |
| 数据分析 | 埋点、指标体系 | + AI 效果指标（幻觉率、准确率） |
| 项目管理 | 敏捷、跨团队协作 | + AI 模型迭代节奏管理 |

## 第一阶段：AI 技术认知（第 1-3 周）

**目标**：建立对 LLM / RAG / Agent 的系统认知，能和技术团队用同一套语言沟通。

### Week 1 · LLM 基础

**学什么**：Transformer 架构、Tokenization 与上下文窗口、主流模型对比、能力边界（什么不适合 LLM）

**本周交付物**：
- 用自己的话写一段 Transformer 解释（≤300 字，讲给非技术听）
- 制作 B 端主流模型对比表（含价格 / 上下文窗口 / 优劣势 / 适用场景）

### Week 2 · RAG 深入

**学什么**：为什么需要 RAG、Embedding 与向量库、Chunking 策略、检索策略、效果评估

**本周交付物**：
- 画一张 RAG 数据流图（从文档输入到答案输出，标清每个环节）
- 本地跑通一个 RAG Demo（用 LangChain 或 LlamaIndex + 任意开源模型）

### Week 3 · Agent 入门

**学什么**：ReAct 模式、Function Calling、记忆机制、多 Agent 协作、评估监控

**本周交付物**：
- 搭一个可运行的简单 Agent Demo（至少 1 个 Tool + Function Calling）
- 记录 Agent 在 3 条不同输入下的行为差异，写一段分析

> **验收**：能向技术解释清楚 Transformer / RAG / Agent；能画出 RAG 数据流图；跑通至少一个本地 LLM + RAG Demo。

## 第二阶段：Prompt 工程与 AI 交互（第 4-6 周）

**目标**：能写出高质量、稳定的业务 Prompt，理解 AI 产品的交互范式。

### Week 4 · Prompt 核心技法

**学什么**：Zero/Few-shot、CoT、结构化输出（JSON）、模板化、减少幻觉

**本周交付物**：
- 针对 ≥5 个 B 端业务场景，各写一条 Prompt 并标注所用技法
- 测试每条 Prompt 在 2 个不同模型上的输出差异，记录一致性

### Week 5 · AI 交互范式

**学什么**：生成式 / 对话式 / 嵌入式三种模式、渐进式披露、可解释性设计、错误处理兜底、人在回路（HITL）

**本周交付物**：
- 写一份 AI 功能 PRD，含 Prompt + 交互流程图 + 异常兜底方案
- 标注 3 个"AI 出错时用户该怎么办"的兜底路径

### Week 6 · 测试与优化

**学什么**：Prompt 版本管理与 A/B、LLM-as-a-Judge、对抗测试、多轮上下文管理、B 端合规

**本周交付物**：
- 建一套可复用的 Prompt 测试 Checklist（至少 10 条检查项）
- 用 LLM-as-a-Judge 对 Week 4 的 5 条 Prompt 做自动评分并记录

> **验收**：业务 Prompt 准确率 >90%；能设计含正常/异常/边界的完整交互；掌握 ≥3 种减少幻觉的策略。

## 第三阶段：AI 产品实战方法论（第 7-9 周）

**目标**：把 AI 能力系统化融入产品工作流——发现、设计、评估、迭代全流程。

### Week 7 · 发现与策略

**学什么**：AI 机会识别、AI 特殊用户研究、价值假设验证、竞品 AI 能力对比、路线图

**本周交付物**：
- 选一个你手头工作中的场景，写一份 AI 功能 MRD（含价值假设 + AI 介入点）
- 做一次竞品 AI 能力对比（至少 3 个竞品，标注差异点）

### Week 8 · 设计实战

**学什么**：AI-PRD 写法、模型选型（自研/微调/API）、数据准备、埋点与指标、成本模型

**本周交付物**：
- 把 Week 7 的 MRD 扩展为完整 PRD，含 Prompt + 交互 + 成本估算 + 效果指标
- 计算该功能的单次调用 Token 成本（输入 + 输出分别计算）

### Week 9 · 系统架构与协作

**学什么**：AI 系统架构（LLM 服务层 / 应用层 / 数据层）、向量库选型、缓存与性能、安全合规、与工程协作流程

**本周交付物**：
- 画一张 AI + B 端系统架构图（标清各层职责和数据流向）
- 写一份技术评审纪要（模拟和工程团队 review 你的 PRD，记录 3 个关键问题）

> **验收**：能独立完成从机会识别到 PRD 的全流程；能画完整架构图；能独立计算 AI 功能成本模型。

## 第四阶段：垂直深耕与作品集（第 10-12 周）

**目标**：选一个方向深耕，产出 1-2 个可展示的作品，准备求职/晋升。

**可选方向**（按你的 B 端背景选）：

| 方向 | 典型场景 | 需补知识 |
| --- | --- | --- |
| AI 知识库 / 企业搜索 | 智能客服、内部问答 | RAG 高级优化、Embedding |
| AI 数据分析 | NL2SQL、智能报表 | NL2SQL、可视化 |
| AI 流程自动化 | 智能审批、文档处理 | Agent 编排、工作流 |
| AI + 垂直行业 | 法律 / 医疗 / 金融 AI | 行业知识 + 合规 |

- **Week 10 · 定方向与 Kickoff**：定方向、定义范围、写 Kickoff 文档。**本周交付物**：选定一个垂直方向 + 一份 Kickoff 文档（含范围、目标、成功标准）
- **Week 11 · 周末冲刺 MVP**：产品发现 → PRD + Prompt → 原型 → 搭出可运行 MVP。**本周交付物**：一个可交互的 MVP 原型（允许简陋，但核心链路必须跑通）
- **Week 12 · 收尾与求职准备**：完善作品集、准备面试话术、梳理转型故事、更新简历、模拟面试。**本周交付物**：① 1-2 个可展示的作品 ② 一段 3 分钟的转型故事 ③ 简历更新含 AI 项目经历

## 转型成功的 5 个信号

当你能做到下面 5 点，说明已经转过来了：

1. **技术对话无障碍**：能和工程聊 Embedding 维度、RAG 召回率、Agent 状态机。
2. **Prompt 即代码**：看到需求第一反应是「这个用 Prompt 怎么实现」。
3. **AI 成本敏感**：做方案本能算 Token 成本和推理延迟。
4. **幻觉意识**：设计时自动考虑「AI 说错了怎么办」。
5. **持续追前沿**：每天 15 分钟看 AI 动态，知道最新模型和框架。
