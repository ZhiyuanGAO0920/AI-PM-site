**先记住一句话**：LLM 不是"理解"了语言，而是学会了"合理地组合词语"的概率机器。它没有一个世界模型来验证事实——这解释了它会幻觉、对最新事件无知、算数会错。所有 AI 产品的设计，本质都是在和这个"概率本质"打交道。

## 一、LLM 基础

- **概率预测**：输出不固定、每次可能不同 → 设计要接受"非确定性"
- **Token**：最小处理单位，中文约 0.5 字 / Token → API 按 Token 计费，中文比英文贵
- **上下文窗口**：一次能"看到"的最大 Token 数，主流已到 1M（≈1500 页 PDF）；但"Lost in the Middle"问题——关键信息放中间容易被遗忘，指令放开头/结尾
- **能力边界（必知）**：
  - 擅长：文本总结、创意写作、代码、翻译、信息抽取、简单推理 ⭐⭐⭐⭐⭐
  - 不擅长：精确数学（本质不是计算器）、实时信息（知识有截止）、事实核验（会编）、长程推理、物理世界、私密数据
- **幻觉**：生成看似合理但错误的内容，分事实性/引用/细节/过度推断四类。B 端对准确性要求极高，必须设计检测机制 + 人工兜底

→ 选型、价格、推理力度维度看 <a href="/reference/llm-selection/">LLM 选型指南</a>。

## 二、RAG（检索增强生成）

- **为什么需要**：补 LLM 的三处短板——知识截止、不懂企业私有知识、幻觉风险。核心思想："开卷考试"，先查资料再说话
- **架构**：离线（文档→分块→Embedding→向量库）+ 在线（提问→向量化→召回→拼 Prompt→生成）
- **Embedding**：把文本变高维向量，语义相近则向量相近；中文私有化首选 BGE-M3 / GTE / M3E
- **Chunking**：分块大小是核心调优参数，中档（512-1024 Token）默认推荐，相邻块留 20% 重叠防切坏
- **检索进阶**：混合检索（语义+关键词）、重排序（Rerank 精排）、查询重写（Query Rewriting）——效果提升的关键，但要权衡延迟和成本
- **评估**：检索看 Recall@K / MRR，生成看 Faithfulness（是否忠实文档）/ Answer Relevance；工具 RAGAS、TruLens
- **B 端落地难点**：权限隔离（不同人看不同文档）、数据安全（私有化/脱敏）、多模态文档（表格/OCR）

→ 完整设计模式看 <a href="/reference/rag-design/">RAG 设计</a>。

## 三、Agent（智能体）

- **是什么**：能自主感知、决策、执行、调工具的 AI 系统；区别于传统 LLM 调用在于多轮自主、有记忆、能规划
- **ReAct**：推理+行动循环（Thought→Action→Observation→…），可追溯、可纠错
- **Function Calling**：让模型识别何时调工具并生成正确参数；工具 description 写清、参数精确、粒度合适是 PM 的设计要点
- **记忆**：短期（当前对话上下文）+ 长期（向量库/结构化/知识图谱）；长期记忆要重点考虑隐私和安全
- **多 Agent**：主管-工人（Supervisor-Worker）、流水线（Pipeline）、协作讨论三种模式；B 端如智能客服按意图分给订单/技术/工单 Agent
- **评估监控**：特有维度——工具选择准确率、参数准确性、任务完成率、错误恢复、成本控制

→ 架构模式 + EIA 实战看 <a href="/reference/agent-arch/">Agent 架构</a>。

## 四、Prompt 工程

- **基本结构**：角色定义 + 任务指令 + 上下文 + 输入数据 + 输出格式 + 约束条件
- **核心技法**：Zero-shot（直接给任务）、Few-shot（给示例，2-5 个）、Chain-of-Thought（一步步想，提升复杂推理）、结构化输出（强制 JSON / 字段定义清晰）
- **减少幻觉 5 招**：明确知识边界（"不知道就说不知道"）、要求引用来源、分步验证、多模型交叉验证、Self-Check

### ⭐ 差异化重点：Prompt 评测方法论（大多数手册没有）

会写 Prompt 是入门，**会系统评测和迭代才是 AI PM 的核心分水岭**。

- **评测集（Golden Set）**：一组"问题-期望回答"对。构成比例——标准场景 50% / 边界场景 30% / 对抗场景（历史 BadCase）20%。先冻结基线，之后每次改动都和基线比
- **迭代日志**：每次改 Prompt 记录变更内容、原因、验证方式、效果对比（通过率/重新生成率/编辑量）、遗留问题、**教训**（反直觉规律不记就会重复踩坑）
- **BadCase 五步复盘**：现象描述→根因诊断（数据/Prompt/模型/架构，由外到内）→修复→验证（跑完整评测集防回归）→教训提炼。分级 P0 事实错误（阻塞发布）/ P1 逻辑错误 / P2 格式 / P3 体验
- **回归测试**：改 A 可能意外影响 B，必须每次跑完整评测集，不能只验改动点

→ 完整模板和范例看 <a href="/learn/prompt-templates/">Prompt 模板库</a>。

## 五、AI 交互设计

- **三种范式**：生成式（一键生成完整内容）、对话式（多轮聊天）、嵌入式（AI 融入现有功能、不显式界面，如自动补全/纠错）
- **渐进式披露**：别一次展示所有 AI 能力。四级——L1 静默辅助 → L2 轻量建议 → L3 主动辅助 → L4 深度交互。例：合同审核从后台提取条款，到高亮风险，到点击生成报告，到打开法务助手追问
- **可解释性（B 端刚需）**：显示置信度、展示推理过程、提供依据来源（"点此看原文"）、对比展示。企业决策要知道"为什么"，合规要能追溯
- **错误处理与兜底**：降级 gracefully（AI 不可用回退传统功能）、让用户掌控（始终给人工介入）、透明沟通（出错解释原因不甩锅）、快速恢复（一键重试 + 保存输入）
- **人机协作（HITL）**：AI 建议人决策 / 人发起 AI 执行 / 人机分工 / AI 监控人处理异常。智能审批例：60% 自动、30% AI 预审+人复核、10% 人审+AI 辅助

## 六、实战方法论

- **机会识别**：AI 适配度 × 业务价值矩阵。B 端高价值点——客户服务、销售支持、数据分析、知识管理（⭐⭐⭐⭐⭐）；评估 Checklist：重复规则性？文本/数据量大？错误成本可控？有人工兜底？ROI 合理？
- **AI-PRD**：比传统 PRD 多出——AI 能力定义（模型/版本/调用方式）、Prompt 设计（System/User 模板 + 示例）、工具调用定义、效果要求（准确率/召回/满意度）、**成本模型**、评估方案、上线标准
- **模型选型**：决策树——数据是否不出境？否→效果极高？是→Opus/GPT-5.6，否→追求性价比→DeepSeek V4 Flash / Qwen。要素：效果/成本/速度/安全/可控性/生态

### ⭐ 差异化重点：成本模型（成本是产品设计的一级约束）

计费 = 输入 Token×输入单价 + 输出 Token×输出单价（输出通常贵 2-6 倍）。示例：客服问答用 DeepSeek V4 Flash，输入 500 + 输出 300 Token、日调用 1000 次 → 单次 $0.000154、月成本约 **$4.6**。

优化策略：模型降级（成本降 50-90%）、缓存常见回答（命中成本≈0）、Prompt 压缩、响应截断。
