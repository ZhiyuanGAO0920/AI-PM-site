AI PM 不是「会玩 ChatGPT 的产品经理」，而是在「业务 + 用户」之外，再叠一层「AI 技术理解」的人。这一页先把要补的能力画清楚。

## 核心能力矩阵

AI PM 的能力可以落在四个象限里，缺一不可：

| 业务理解 | AI 技术 | 产品设计 | 运营评估 |
| --- | --- | --- | --- |
| 行业知识 | LLM | 需求分析 | Eval（评估） |
| 用户洞察 | RAG | 方案设计 | BadCase 管理 |
| 数据驱动 | Agent | PRD | 迭代优化 |
| 规则抽象 | Prompt | 原型 | 监控 |

> **规则抽象**是 B 端 PM 独有、却最被忽视的一项。AI 系统里哪些该用确定性的规则、哪些交给模型判断，这个边界划分能力，是传统 PM 转 AI PM 时最大的加分项。

## 怎么补：每个象限的能力路径

画完矩阵，最实际的问题是"我缺的那块去哪补"。下面按象限给路径，能站内解决的标了链接：

### 业务理解（你已具备，重点是"翻译"）
- 你已有业务流程、权限、数据流底子，不用从头学
- 要补的是：把"业务流程"翻译成"AI 可介入的节点"——哪些环节适合 AI、哪些必须确定性规则
- 练法：拿手头一个业务，画一张"AI 介入点地图"（哪些步骤能自动化、哪些必须人工兜底）

### AI 技术（从概念到能对话）
- LLM 原理 / RAG / Agent 核心概念 → 看 <a href="/reference/llm-selection/">LLM 选型</a>、<a href="/reference/rag-design/">RAG 设计</a>、<a href="/reference/agent-arch/">Agent 架构</a>
- 目标：能和工程聊 Embedding 维度、召回率、Agent 状态机（标准见 <a href="/learn/12-week-plan/">12 周计划</a> 的"转型 5 信号"）
- 别陷入调参细节，PM 要的是"理解边界 + 能判断对错"

### 产品设计（AI 交互范式是新增项）
- 传统 PRD 之外，要补：Prompt 设计、AI 交互范式（生成式/对话式/嵌入式）、兜底与人在回路
- 工具看 <a href="/learn/prompt-templates/">Prompt 模板库</a>；方法看 <a href="/learn/12-week-plan/">12 周计划</a> 第二阶段

### 运营评估（AI PM 的分水岭）
- 这是传统 PM 最缺、AI PM 最关键的：上线不是终点，是评估起点
- 要建：评估指标（幻觉率/准确率）、BadCase 管理、监控闭环
- 入门看 <a href="/reference/eval-system/">AI 评估体系</a>；真实踩坑看 <a href="/cases/badcase-library/">BadCase 库</a>

> **补能力顺序建议**：先 AI 技术（能和工程对话）→ 再产品设计（能写 AI-PRD）→ 最后运营评估（能持续迭代）。业务理解你已有，别在这块浪费时间。

## 四个成长层级

### L1：AI 工具使用者
- 会用 Dify / Coze 搭基础对话机器人
- 会用 ChatGPT / Claude 辅助日常工作
- **局限**：只能做简单 Demo，落不了企业级

### L2：AI 产品方案设计师
- 理解 RAG / Agent / Prompt 核心概念
- 能设计 AI 产品技术方案，能判断业务是否适合 AI
- **标志**：独立完成一个 AI 产品从 0 到 1

### L3：AI 系统架构师
- 能设计 Multi-Agent 系统
- 建立评估体系与优化闭环，具备企业级治理能力
- **标志**：搭出一个完整的 AI Product Copilot

### L4：AI 产品负责人
- 管理 AI 产品完整生命周期，驱动业务增长与创新
- 建立团队 AI 能力
- **标志**：形成团队级的 AI Product Management 操作系统

## AI PM 与传统 PM 的本质区别

| 维度 | 传统 PM | AI PM |
| --- | --- | --- |
| 核心问题 | 需求 vs 功能 | 问题 vs AI 能力 |
| 产出 | PRD + 原型 | 方案 + Agent + Eval |
| 上线后 | 功能验收 | 持续评估优化 |
| 知识要求 | 业务 + 用户 | 业务 + 用户 + AI 技术 |
| 工具链 | Figma / Axure | Dify / Claude / 知识库 |
| 风险 | 功能缺陷 | 幻觉 / 不可控 / 安全 |

## 四条关键原则

1. **AI 不是目的，是手段** —— 先判断「这事需不需要 AI」。
2. **可靠 > 智能** —— 企业级 AI 的核心是确定性，不是多聪明。
3. **评估驱动迭代** —— 没有评估，就没有优化方向。
4. **知识就是壁垒** —— AI PM 自己的知识库（行业 + 技术 + 踩坑）是核心竞争力。
